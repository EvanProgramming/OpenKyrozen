# V3 Issue #241 — Working Plans and Task Lifecycle

> Issue-specific plan for [#241](https://github.com/EvanProgramming/OpenKyrozen/issues/241), based on the reviewed #264 migration branch. #242 will add richer atomic edit, ordering, and dependency operations.

**Goal:** Keep simple work unplanned, allow optional plans for medium work, and require an explicit, mutable, durable Working Plan before substantial complex work. The model proposes strategy; runtime state owns plan and task identity and validates lifecycle transitions.

**Scope boundary:** Reuse `TaskManager`, the existing `tasks` repository, ToolRegistry, and the new ordered SQLite migrations. Add only the persisted plan identity/state and the typed `update_plan` entry needed by this contract. Full revision history, atomic multi-operation edits, dependency validation, parallel scheduling, and AgentEngine loop replacement remain later issues. Keep textual TaskList/TaskDone confined to legacy compatibility paths while the native structured path adopts the typed plan contract.

## Caller and persistence map

- `openkyrozen/tasks/engine.py` and `tasks/models.py`: task identity, receipt correlation, evidence-backed completion, status transitions, recovery, and legacy text adapters.
- `openkyrozen/persistence/database.py` and `persistence/tasks.py`: schema version 4 migration and durable plan/task association, extending the migration framework introduced by #264.
- `openkyrozen/agent/initial_response.py`, `protocol.py`, `action_rounds.py`, `prompts.py`, and `runtime.py`: complexity policy and current TaskList/TaskDone protocol; retain simple-task behavior and prevent complex work from reaching substantial execution without a plan.
- `openkyrozen/tools/manifest.py` and workspace binding: expose typed `update_plan` through the authoritative registry without a global bound executor.
- Existing task, interaction, web/TUI, and acceptance tests: preserve stable IDs, scoped recovery, compatibility behavior, and visible plan state.
