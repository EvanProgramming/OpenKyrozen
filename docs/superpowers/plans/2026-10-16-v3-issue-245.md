# V3 Issue #245 — Strategic Plans Implementation Plan

> **For agentic workers:** execute this indexed plan task by task; keep the PR based on #242 and do not merge it.

**Goal:** Preserve Plan Mode as a non-executing, versioned user approval of stable objectives, acceptance criteria, workspace scope, permitted effects/capabilities, and risk limits, with a linked mutable Working Plan.

**Architecture:** Extend the existing `InteractionController` event-sourced proposal lifecycle and `TaskManager` transaction. Keep proposals and legacy message shapes as compatibility projections; persist the accepted Strategic Plan and linked Working Plan/tasks in the existing event and task stores, atomically. Strategic acceptance remains separate from capability grants, tool approvals, task evidence, and completion.

**Tech Stack:** Python 3.12–3.13, unittest, existing SQLite repositories and interaction event log; no new dependency.

**Spec:** GitHub issue [#245](https://github.com/EvanProgramming/OpenKyrozen/issues/245), requirements R069–R073, R077, and R080; approved batch plan in the task history.

## Global Constraints

- Plan Mode must not execute a proposal.
- Approval covers objectives, acceptance criteria, workspace paths, effect/capability categories, and the existing normal/high risk ceiling.
- Working Plan edits may adapt execution but cannot redefine approved intent.
- Plan approval never grants capabilities or replaces tool approval.
- Acceptance and its linked Working Plan/tasks/events commit atomically; duplicate acceptance is idempotent and stale versions fail without task creation.
- Preserve existing proposal/message shapes through explicit compatibility defaults; missing legacy bounds never widen scope automatically.
- No new dependency, paid provider call, or unrelated V3 work.

## Files in Scope

- `openkyrozen/agent/modes.py`: proposal validation, Strategic Plan version/fingerprint, controller state/acceptance, and user-facing rendering.
- `openkyrozen/agent/prompts.py`, `openkyrozen/agent/protocol.py`, `openkyrozen/agent/loop.py`: proposal contract, bounded defaults, acceptance and terminal lifecycle integration.
- `openkyrozen/tasks/engine.py`, `openkyrozen/tasks/ports.py`, `openkyrozen/persistence/tasks.py`, `openkyrozen/persistence/store.py`, and SQLite migration code: atomic creation of the linked Working Plan and event records, with per-task objective/criterion references.
- `tests/test_interaction.py`, `tests/test_working_plans.py`, `tests/test_sqlite_migrations.py`: contract, compatibility, lifecycle, and durability regressions.
- `docs/tasks-and-automation.md`, `docs/superpowers/plans/index.md`: user-facing contract and this indexed plan.

## Review Focus

- A stale or duplicate acceptance must never create duplicate tasks or accept a different version.
- A legacy proposal without bounds must not imply workspace or authority expansion.
- Revisions must keep stable objective/criterion identifiers where meaning is unchanged and create new identities when meaning changes.
- Failed persistence must leave both interaction state and Working Plan state unchanged.
- Completion and cancellation must remain distinct; cancellation cannot emit successful Strategic Plan completion.
