# V3 Issue #233 — Structured Tool Arguments and MCP Implementation Plan

> Issue-specific plan for [#233](https://github.com/EvanProgramming/OpenKyrozen/issues/233), stacked on the #261 security-boundary PR.

**Goal:** Make JSON objects the native tool-call contract from provider/MCP entry through authorization, registry validation, executor dispatch, receipts, and observers, while keeping text APIs explicitly compatibility-only.

**Architecture:** Extend the existing `ToolRegistry` and `AgentRuntime.execute_call()` boundary. Built-in executors live in `openkyrozen/tools`; MCP and other surfaces adapt only at their public compatibility edges. Security policy remains in runtime/security. No parallel catalog or second dispatcher.

**Tech stack:** Python 3.12–3.13, standard library and current dependencies, `unittest`.

**Spec:** V3 issue #233 (R014–R018), with related issue [#226](https://github.com/EvanProgramming/OpenKyrozen/issues/226).

## Constraints and compatibility

- Add no dependency, paid provider call, provider continuation, or execution retry.
- JSON serialization is allowed for validation, fingerprints, and persistence only; never use serialized or pipe-joined strings to transport native executor arguments.
- All 48 built-in `ToolSpec` executors accept object arguments and return `ToolResult`; retain public text APIs and `AVAILABLE_TOOLS` through explicit adapters.
- Legacy custom string executors remain compatibility-only. Native custom registration requires a declared object schema and typed result contract.
- Keep approvals, capabilities, workspace and child scope enforcement from #261 at the same shared runtime boundary.
- Preserve canonical names, aliases, argument aliases, snapshots, replacement/removal, MCP output content, and registry-derived documentation.

## Caller and contract map

- `openkyrozen/tools/manifest.py`: current schema validation, `ToolSpec` legacy converters, registry invoke/result, `ToolMapping` compatibility views, descriptors and snapshots.
- `openkyrozen/tools/`: built-in typed executor definitions and adapter bindings (48 registered specs, including memory, discovery, graph, orchestration and integration tools).
- `openkyrozen/agent/runtime.py` and `openkyrozen/agent/executor.py`: `execute_call`, canonical policy validation, mutation/effect fingerprints, receipts and observer arguments.
- `openkyrozen/interfaces/mcp/server.py` and `openkyrozen/interfaces/web/service.py`: MCP currently translates arguments through `_mcp_string_arguments`; remove this path from native MCP calls.
- CLI/TUI/web/task/subagent/learning callers and tests: preserve old text behavior via compatibility adapters while routing structured callers through the typed boundary.
- Generated `docs/tool-inventory.md` and its drift check: regenerate from the final catalog.

## Task 2 — Enforce canonical JSON-object schemas

- [ ] Exercise required and unknown fields, nested objects/arrays, combinators, bounds, enums, nonfinite numbers, wrong primitive types, and coercion attempts.
- [ ] Extend the existing registry validator only where cases fail; reject invalid arguments before executor invocation with typed `invalid_arguments` outcomes.
- [ ] Keep schema evaluation aligned with the catalog's already supported vocabulary and reject unsupported schema keywords rather than silently ignoring them.

## Task 3 — Migrate built-ins with their compatibility edges

- [ ] Replace generic string schemas with meaningful object schemas: files, shell, Git/GitHub, browser, graph, memory, calculation, discovery, and orchestration.
- [ ] Keep text/public `AVAILABLE_TOOLS` callers working through explicit edge adapters; resolve aliases there and reject conflicting alias values.
- [ ] Preserve legacy custom executors as compatibility-only; require object schema and typed executor for native custom registration.

## Acceptance and known limits

PASS means native provider/MCP object arguments reach their typed executor unchanged and schema violations are rejected before side effects. Compatibility text adapters may translate legacy calls. The malformed search argument is independently covered; provider continuation/model repair and unimplemented platform sandboxing are outside this issue. Live providers are not called.
