# V3 Issue #261 — Secure Typed Tool Invocation Implementation Plan

> Issue-specific plan for [#261](https://github.com/EvanProgramming/OpenKyrozen/issues/261). Complete this work before #233.

**Goal:** Ensure every tool call is authorized against its exact arguments and cannot exceed the configured, surface, interaction, parent, workspace, or assigned-child authority.

**Architecture:** Keep policy in `openkyrozen/security`, enforcement and receipts in `openkyrozen/agent`, and schemas/executors in the existing `ToolRegistry`. Introduce one immutable approval request and typed runtime entry point; preserve current string APIs only through compatibility adapters until #233 migrates built-ins.

**Tech Stack:** Python 3.12–3.13, standard library, `unittest`, existing Go Bubble Tea TUI.

**Spec:** Approved V3 batch plan, issue #261 (R179–R182, R184–R186).

## Global Constraints

- Add no dependency, paid provider call, or persistence of executable source.
- Capability checks remain in the runtime boundary; registry invocation remains capability-only.
- Approval responses remain separate from Strategic Plan approval and user clarification.
- The active grant is the intersection of all authority bounds and cannot increase during renewal or delegation.
- Assigned children may mutate only explicitly assigned paths through enforceable file tools; opaque shell, Git, browser, and custom mutations are denied.
- Preserve existing text APIs and event fields while adding typed adapters.

## Review Focus

- Call arguments or registry policy change while approval is pending — bind the approved snapshot to execution and deny stale operations.
- Nested capability overrides or expired-token renewal — renew only the original bounded grant.
- Large or secret-bearing approval payloads — show complete nonsecret details without leaking secret values or silently truncating.
- Paths that resolve through symlinks or change during approval — resolve and recheck within the active workspace and child scope before execution.
- Read-labelled Git commands that write output or invoke external programs — reject those options before execution.
