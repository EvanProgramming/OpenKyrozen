# V3 Issue #229 — Native Provider Tools Implementation Plan

> Issue-specific plan for [#229](https://github.com/EvanProgramming/OpenKyrozen/issues/229), covering R003 and R005. Start from verified `main` `be3d035`; finish and review before #230.

**Goal:** Add schema-backed native tool requests and lossless tool-result history across every shipped provider adapter, without textual control parsing or adapter-side execution.

**Architecture:** Keep shared call/reply/history validation in `openkyrozen/providers/models.py`; adapter serialization in each provider module; registry selection in the existing runtime provider boundary in `openkyrozen/providers/calls.py`. Preserve fallback, deadlines, retry budgets, usage accounting, and existing text APIs. Continuation state stays SDK-independent and bound to the provider/model that produced it.

**Tech Stack:** Python 3.12–3.13, existing provider SDKs, standard library, `unittest`, local HTTP/SDK-shape fixtures.

## Constraints and compatibility

- No new dependencies, paid calls, executable transport of provider SDK objects, or automatic tool execution inside adapters.
- Keep legacy calls unchanged when `tools=None`; reject unsupported schemas or malformed history before transport.
- Provider-visible tools are canonical registry names filtered by the runtime's effective capability grant.
- Once a native call has been returned, follow-up requests remain pinned to its responding provider and request model.
- Keep opaque provider continuation separate from text, normal metadata, receipts, logs, and exception diagnostics.
- Preserve existing fallback model mapping and exactly-once usage accounting for the initial request.

## Review focus

- Every adapter preserves the provider's native assistant/tool result shape and call order, including reasoning/signature blocks needed for replay.
- History validation rejects duplicate, orphaned, missing, mismatched, and non-contiguous replies before making a request.
- Tool schemas are not weakened by adapter conversion; strict-mode defaults do not change optional-field semantics.
- Fallback cannot move a continuation to a different provider or execute/replay a tool call.
- Runtime authority filters declarations; providers receive no executor references.
