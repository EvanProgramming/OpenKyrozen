# OpenKyrozen V3 matched evaluation

The frozen cohort contains 30 fixtures across ten task categories, with three matched repeats per fixture on V2 `v2.0.8` (`1bfc82c793df49e76097061ec5adfef0e4e2e883`) and the V3 candidate. It includes dedicated replanning, Strategic Plan scope, material-revision approval, and plan-churn scenarios. `benchmarks/v3_matched_live.py` creates isolated workspace and state for each run, verifies outcomes outside the model, records token/request accounting, and resumes only a report whose hash is pinned in its original budget ledger. Strategic Plan fixtures preserve their accepted workspace-local read/write authority. The independent harness runs acceptance tests after checking original-test integrity; the worker does not gain shell/process authority from the fixture. Scope evidence accepts either a live strategic task binding or a matching completed-plan event for the exact accepted plan ID, version, and fingerprint. Process cancellation is checked against the OS process group or process tree; permission scenarios require denied runtime receipts and reject secret disclosure.

The `--repo` checkout must contain the pinned V2 commit so the runner can extract its source with `git archive`. The CI full-suite jobs fetch complete history and verify that exact commit before running tests; for a shallow local checkout, fetch the V2 baseline first.

The formal finalization campaign uses the [DeepSeek CNY command below](#deepseek-cny-campaign), with its cumulative CNY 15 cap. The Panstar configuration remains a separate compatibility path; its historical USD allowance does not authorize spending in that campaign.

Independent acceptance also needs the worker's answer, tool receipts, task state and plan events after its temporary workspace is removed. The parent retains those results outside the checkout with exact candidate/cohort/apparatus/row identity and content hashes. Provider credentials are redacted from retained worker strings; credential-bearing output remains incomplete, so redaction cannot turn a failed observation into a passing verdict. The relay's accounting journal continues to store request hashes and usage rather than prompts or answers. Missing, modified or foreign worker artifacts cannot qualify a reusable row or a complete report. Automated outcome checks and the identical-task-snapshot churn proxy do not replace the predeclared independent QA, reproduction and planning review; no comparison or routing benefit is claimed without the required evidence.

The repaired cohort keeps the same 30 IDs, ten categories, three repeats and two arms. It adds in-process multi-file API changes, behavior-preserving shared-helper refactors, independently correlated Git tool receipts, and eleven-turn context scenarios. Both arms receive an explicit context window of 1,000,000 tokens for ordinary fixtures and 16,384 for context fixtures, with 4,096 output tokens reserved. Provider-port observations measure the actual dispatched messages, including compaction requests, without changing either runtime's behavior. Estimated components remain distinct from provider-reported usage; unavailable fields stay unknown.

The paired long-context oracle checks the same facts, supersession, complete scripted turns and outbound bounds for both arms. V3 compaction observation is a separate feature acceptance condition and does not alter paired task success. Checkpoints bind the canonical fixture digest and observer, verifier, metric and relay hashes. A changed apparatus cannot reuse old rows; historical calls still count toward cumulative spending.

The local authenticated Responses relay pins `gemini-3.1-flash-lite`, caps output at 4,096 tokens, reserves worst-case spend before forwarding, and stores request hashes and usage rather than prompts or answers. It moves system-role messages from `input` to Responses `instructions` for both benchmark arms; when no other input remains, it sends `Continue.`. It stops consuming a stream at its terminal event, preserving unknown usage as a held reservation without attempting to settle the same attempt twice. Worker failures record the exit code and exception class without persisting stderr or its potentially sensitive details. `response.failed` and HTTP error events record only an ASCII error code of at most 80 characters; HTTP error bodies are capped at 64 KiB for parsing, and free-form provider messages are never stored. Failed workers with partial usage are retried on resume; complete usage and a successful exit are required before a fixture row can be reused. The cumulative Panstar cap is US$20. Panstar's quoted rates are $0.033/1M input, $0.275/1M output, and $0.0033/1M cache reads; cache writes are charged at the input rate because Panstar quoted no separate rate. The CNY SQLite ledger uses the recorded 2026-10-23 USD/CNY rate of 6.67135 and records both the quote and FX source in pricing metadata. Unknown usage retains its reservation. Every fresh run requires an explicit `--prior-hold-usd` equal to all earlier settled spend and held reservations, including unknown attempts; never reuse a smaller reservation. Before every run, reconstruct cumulative exposure from the original report and budget ledger as settled spend plus every reserved or unknown attempt. Do not use a stored or copied exposure amount; if the source reports and ledger are unavailable, do not start the campaign. The runner requires the hold explicitly and records it in the report. Existing partial reports remain inconclusive and are not used as evaluation evidence. The application-shaped native tool continuation was verified; a separate `previous_response_id` diagnostic was rejected by the gateway and is not used by OpenKyrozen. Set `KYROZEN_BENCHMARK_API_KEY` and `KYROZEN_BENCHMARK_BASE_URL` from the approved provider configuration; the default endpoint is `https://ai.panstar.ai/v1`.

Before reading provider credentials or starting campaign requests, the runner probes the OS filesystem sandbox. The cohort requires working filesystem restrictions for its permission and scope checks, so an unavailable backend blocks the campaign without provider spend. This benchmark prerequisite does not change the application's best-effort sandbox default.

After reconciling the original reports and ledger, set `VERIFIED_PRIOR_HOLD_USD` to all prior settled spend plus every still-reserved or unknown attempt. Run the complete cohort from a clean candidate checkout, writing the report and budget ledger outside it:

```sh
python -m benchmarks.v3_matched_live \
  --source . --repo . \
  --output /outside/checkout/v3-matched-report.json \
  --budget-db /outside/checkout/v3-matched-budget.sqlite3 \
  --limit-usd 20 \
  --prior-hold-usd "$VERIFIED_PRIOR_HOLD_USD"
```

The report is descriptive evaluation data, not release authorization. A result is conclusive only when all 180 matched rows have complete provider usage, all independent verifiers pass, the full paired success interval improves, token and request reductions meet their thresholds, and no safety or protocol-recovery control fails. Missing or unknown usage, failed checks, budget exhaustion, or an incomplete run remains inconclusive. Any code change creates a different candidate SHA and requires a new matched run.

## DeepSeek CNY campaign

The in-tree `benchmarks.v3_deepseek` CLI uses the same frozen 180-row cohort and unchanged comparison thresholds, with immutable DeepSeek configuration. It pins the official `https://api.deepseek.com` Responses endpoint and `deepseek-flash` alias (served model `DeepSeek-V4.1-Flash-1017`). Peak prices are CNY 2/M input, 8/M output, 0.04/M cache reads, and conservatively 2/M cache writes, from the [official pricing table](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/). Every request reserves exactly CNY 2.032768 for 1,000,000 input and 4,096 output tokens. Requests are serial through stream completion. Unknown usage keeps its entire reservation; retries and the required metered smoke share the cohort ledger. Smoke calls remain in its journal and do not count toward the 180 matched rows.

The cumulative cap is **CNY 15 including previous campaigns**. Supply original prior ledgers; the reader opens them in SQLite read-only mode, independently reconstructs settled charges from usage, retains reserved/unknown amounts, and deduplicates identical attempt IDs across copies. New aggregate carryovers include the underlying attempt records and a SHA256 manifest so later campaigns can be reconciled with their original ledgers without double counting or releasing unknown exposure. Missing sources, conflicting records, invalid provenance, unknown pricing, and overruns fail closed. Original campaign `run1/budget.sqlite3` and its `evidence/budget.sqlite3` copy represent one campaign, not two. The code has no fixed candidate SHA or machine-local path.

After the offline protection gates pass, use a clean, signed frozen candidate and output paths outside it. The CLI verifies the configured candidate and release-owner signature; the runner probes the OS sandbox and protected worker/managed shell before reading `KYROZEN_BENCHMARK_API_KEY` from the environment. It then performs and checkpoints a two-request native-tool smoke through the same relay before starting cohort workers: a typed `echo_probe` call must carry an unpredictable value, its `function_call_output` must use the returned call ID, and the final assistant answer must include that value. Both requests require complete usage; the probe has no external side effects. The checkpoint pins the two verified attempt IDs. A previously settled smoke for the same candidate can be reused; failed or unknown smoke attempts remain charged or held when retrying.

```sh
python -m benchmarks.v3_deepseek \
  --source "$FROZEN_SOURCE" --candidate-sha "$FROZEN_CANDIDATE_SHA" \
  --repo "$REPOSITORY_WITH_V2_HISTORY" \
  --output "$CAMPAIGN_OUTPUT/report.json" \
  --budget-db "$CAMPAIGN_OUTPUT/budget.sqlite3" \
  --prior-ledger "$ORIGINAL_PRIOR_LEDGER" \
  --limit-cny 15
```

CNY checkpoints report their actual CNY cap, prior exposure and remaining balance without an exchange-rate workaround. A new request cannot be reserved once cumulative settled spend plus outstanding holds exceeds CNY 12.967232. A completed smoke is provider compatibility/accounting evidence only; it does not satisfy the cohort or authorize release.
