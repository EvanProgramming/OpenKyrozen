# Root-cause bug fixing

## Trigger
Use for reported bugs, errors, regressions, or unexpected behavior.

## Steps
1. Reproduce the observed failure with the original command or a focused test.
2. Inspect the relevant callers and shared implementation to find the root cause.
3. State the diagnosis and intended correction before editing when interacting with the user.
4. Make the smallest complete fix, including callers and regression coverage.
5. Run the reproducer, focused tests, and relevant project checks.
6. Report what changed and any remaining uncertainty.

## Verify
Do not claim a fix from source inspection alone. If reproduction is unavailable, explain the limitation rather than guessing.
